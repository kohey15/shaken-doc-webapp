# 車検書類作成システム(スマホ専用Webアプリ版)

PCを一切使わず、**スマートフォンのブラウザだけで完結する**車検・名義変更書類作成システム。
旧版(`ShakenDocSystem`、Python/FastAPIサーバー版)を土台に、OCR・PDF生成のロジックを
すべてブラウザ内で完結するJavaScriptへ移植したもの。サーバー・バックエンドは存在しない。

## 構成

- **OCR**: PaddleOCR.js / PP-OCRv5 mobile（Web Worker・WASMによる端末内認識）。罫線ではなく、認識した「氏名」「住所」と右側の文字の位置関係から抽出
- **PDF生成**: pdf-lib.js(サーバー版のPyMuPDFから移植。升目座標の数値は完全に同じものを使用)
- **車検証連携**: iPhone・Android共通のJSONファイル取り込み。AndroidではWeb Share Target（共有先）にも対応
- **オフライン動作**: Service Worker(`sw.js`)がアプリ本体・帳票テンプレート・フォントを
  キャッシュし、通信できない環境でも動作する
- **印刷**: スマホのOS標準の印刷機能(`iframe.contentWindow.print()`)。プリンターが
  Mopria(Android)/AirPrint(iPhone)に対応している必要がある

個人情報(車検証データ・撮影画像・生成書類)は、この端末の中だけで処理され、
どこにも送信されない。

## iPhone・Androidのファイル取り込み

①で手続きを選び、②「車検証の読み込み」のファイル選択から、車検証閲覧アプリで保存したJSONファイルを選びます。iPhoneでは車検証閲覧アプリの「車検証情報読み込みファイルを保存」でJSON形式を選び、共有画面の「“ファイル”に保存」で保存します。中古新規で②が非表示の場合は、③で「車検証からコピー」を選ぶと表示されます。

PDF・XML・CSV・写真の車検証取り込みには対応しません。UTF-8 JSON（BOM付きも可）、上限5MB、CertInfo内または直下に車台番号CarNoがあるデータが対象です。取り込みは端末内で完結し、ファイルをアップロードしません。入力済み車両情報の入れ替えには確認を表示し、不正なファイル・取り消しでは現在の入力を維持します。同じファイルの再選択も可能です。氏名・住所は③で「車検証からコピー」を選択した欄だけに反映します。車庫証明で入れ替える場合は、車両情報・使用本拠・現在の登録番号も新しい車検証から更新します。保管場所の住所・警察署はそのままなので確認してください。

実装は共通Webのファイル選択を使います。iPhone実機でのファイル選択・OCR・PDF印刷の通し確認は別途必要です。

## 継続車検の重量税の自動判定

車検証JSONの `CarWgt`、`NoteCarWgt`、`Use`、`PrivateBusiness`、`FuelClass`、`Firstregistdate*`、`Grantdate*`、`ValidPeriodExpirdate*`、`Model`、`NoteInfo` を正規化して判定します。検査予定日（支局等で手続きする日）は当日を初期表示し、変更できます。日付・有効期間・車両区分・車台番号を変更した場合とPDF生成時に再判定し、前の計算金額を残しません。

対象は継続検査、登録車、自家用乗用車、1年または2年、車両重量3t以下、検査予定日2026-05-01～2028-04-30です。乗用車の車両重量を500kg刻みで切り上げ、年数に応じて算定します。課税重量が曖昧な二段記載、軽・貨物・事業用・ディーゼル、中古新規、3年、収録期間外等は自動判定しません。

確定した税額は納付税額欄へ印字します。要確認の場合は画面とPDFプレビューの案内に理由を表示し、納付税額欄は完全に空欄にして手書きできます。免税を確認できた場合は金額0と備考「免税」を印字し、未判定のnullと区別します。氏名・住所・登録番号などの出力は継続します。課税重量が明確な対象車両では車両重量も印字します。

判定を許可している根拠:

- ガソリン／LPG（通常のハイブリッドを含む）の型式識別記号ABA/CBA/AAA/CAA/3BA/4BA/3AA/4AAで、燃費・優遇等の備考との不一致がないものはエコカー外。経年区分は初度登録月から154か月（12年10か月）／214か月（17年10か月）を境に判定します。
- 平成30年排出ガス50%・75%低減の5BA/6BA/5AA/6AAは、備考に令和2年度（平成32年度）燃費基準達成と令和12年度燃費基準達成率が明記され、一致する場合のみ判定します。80%以上は本則、80%未満はフローの13年未満税率。旧登録の120%以上は初回免税の経過措置を確認するため空欄にします。
- 電気自動車ZAA（2023年5月以降登録）、および2026年5月以降登録の上記125%以上車は、初度登録月に交付され3年有効の車検証で初回継続と確認でき、満了日から15日以内等の条件を満たす場合のみ免税と判定します。再交付等でこの根拠を確認できない場合は空欄です。
- 備考未取得・「他あり」等の省略・改造・特例・矛盾・使用中の車台番号との不一致は空欄です。備考にある前回の納付税額は次回税額に転用しません。DBA等や燃費記載が足りない車両も、通常税率と推測しません。

判定自体は端末内で完結し、外部照会APIへ車両情報を送信しません。任意で公式照会を開き、要確認車の税額を確認できます。税制改正時は判定条件と税率を更新してください。対応範囲の追加は境界条件テストとPDFの実印字確認を伴います。

根拠（2026年10月27日確認）:

- 国交省・2026年5月以降の継続検査フロー／経年区分／税額表: https://www.mlit.go.jp/jidosha/content/001884517.pdf
- 国交省・排出ガス識別記号: https://www.mlit.go.jp/common/001179991.pdf
- 財務省・2026年税制改正（電気自動車等の2回免税）: https://www.mof.go.jp/public_relations/finance/202604/pdf/202604all.pdf
- 車検証JSON仕様・公式サンプル: https://www.denshishakensho-portal.mlit.go.jp/business/application/
- 次回税額の公式照会（利用者による確認用）: https://www.nextmvtt.mlit.go.jp/

## 氏名・住所の入力方法

各手続きの③「氏名、住所記入欄」で、当事者ごとに「車検証からコピー」「直接入力」「住民票・印鑑証明をカメラで読み取る」の三択を選べます。初期状態は直接入力で、読み取りを選んだ場合だけカメラ・写真選択を表示します。三つの方法は同じ編集可能な氏名・住所欄を使用し、④に重複した当事者入力欄はありません。

「車検証からコピー」を選んだ当事者に限り、正規化された使用者の氏名又は名称を氏名欄へ、使用者の住所を住所欄へコピーします。未読込なら②の読み込みを案内し、後で受信した情報も選択中の欄へ反映します。「再コピー」も利用できます。所有者の情報を使う欄では、使用者と異なる場合に所有者情報を入力する説明を表示します。使用者が「所有者に同じ」を表す正式な省略値の場合は正規化処理で解決します。それ以外の使用者情報が不足している場合は所有者から推測せず案内を表示します。

直接入力やOCRの欄は車検証の受信では上書きしません。直接入力・OCRへの切り替えで氏名・住所は消去しません。OCR以外へ切り替えるとカメラを閉じ、読み取り途中の古い結果が入力内容を上書きするのを防ぎます。コピー・読み取りの結果は必ず確認・修正してください。

## OCRの更新・検証

カメラ撮影と「保存した写真から読み取る」の両方に対応します。モデルと実行データは約46MBで、初回読取時に同じ公開先から取得し、端末のCache Storageに保存します。写真や認識値は保存用キャッシュに入れません。

住所の折り返しは、文字行の傾き・左端の位置・次の項目名を使って結合します。旧住所、本籍、世帯主は対象にしません。複数の氏名候補があれば対象者を選択します。切り出した文字画像と入力値を必ず照合してください。

開発者向けの再構築:

```text
npm ci
npm run build:ocr
npm test
```

配信には `assets/ocr/v5/` 全体が必要です。`js/ocr.js` だけの差し替えでは動きません。公開先でNode.jsやOCRサーバーを動かす必要はありません。依存ライブラリ・モデルの出典は `THIRD_PARTY_NOTICES.md` を参照してください。

認識プログラムを更新するときは `js/ocr.js` の `OCR_WORKER_VERSION` を更新してください。モデル・実行基盤の互換性を変更する場合はアセットフォルダーと専用キャッシュの版も更新します。

提供された地紋入り実写真2枚で、氏名・住所の4項目が正解と一致することをブラウザ上で検証しています。一般的な帳票すべてやスマホ実機の処理速度を保証するものではありません。

## 車庫証明申請書（長野県・普通車）

手続きの種類から「車庫証明申請書（長野県・普通車）」を選び、申請者情報、車名・型式・車台番号・寸法、使用の本拠、保管場所、提出先警察署、電話番号を入力します。申請日・郵便番号・使用権原・連絡先・新規／代替等は必要に応じて記入できます。

車検証の共有データに含まれる `CarName`、`Model`、`Length`、`Width`、`Height`、`UseheadqrterChar` 等を引き継ぎます。③で「車検証からコピー」を選ぶと使用者氏名・住所を申請者欄へコピーします。申請者と同じか確認してください。住民票・印鑑証明のOCRでも入力できます。

長野県警の公式ひな形 `templates/shako_nagano.pdf` の2ページへ同じ内容を入力します。証明番号・証明日・警察署長等の行政記入欄は空欄です。自認書、使用承諾証明書、所在図・配置図、軽自動車の届出書、電子申請送信は対象外です。

公式様式・記載例（2026年10月27日確認）: https://www.pref.nagano.lg.jp/police/shinsei/koutsu/shakoshomei.html

### 保管場所から管轄警察署を自動入力

「申請者住所を保管場所にコピー」ボタンで③の申請者住所を駐車場の住所欄へコピーできます。申請者住所が空欄なら案内を表示して既存値を保持します。保管場所に異なる入力があれば駐車場名・区画番号を含む上書き確認を表示します。コピー後は編集でき、管轄警察署も再判定します。

`js/police-jurisdictions.js` に長野県警の管轄区域表を収録しています（2026年10月27日確認）。車庫証明の提出先は保管場所（駐車場）の位置で決まり、申請者住所や使用の本拠の住所からは判定しません。保管場所の住所は手入力です。

県内77市町村のうち75市町村は市町村名で一意に判定し、長野市・塩尻市は市内に複数管轄があるため宛先を空欄にして手入力を案内します。県外、不明住所も推測せず手入力を案内します。県名・郡名の省略、郵便番号、全角空白、駒ケ根／駒ヶ根表記を扱います。町名や建物名の途中にある市町村名では判定しません。

警察署は手入力で修正でき、再判定ボタンも使えます。保管場所を編集したら警察署を再判定・クリアし、前住所の宛先が残らないようにします。管轄の判定処理は外部API・通信・位置情報を使用しません。証明申請の要否や適用除外地域を判定する機能は含みません。

管轄表の出典: https://www.pref.nagano.lg.jp/police/keisatsusho/

提出先の根拠: https://www.pref.nagano.lg.jp/police/shinsei/koutsu/shakoshomei.html

## 一時抹消登録（普通車）

「一時抹消登録（普通車）」から車検証の登録番号・車台番号を引き継ぎ、③に所有者氏名・住所を入力して申請書（第3号様式の2）と手数料納付書を作成します。③の車検証コピーは使用者情報なので、所有者と同じか確認してください。代理申請を選ぶと代理人入力と委任状が有効になります。本人申請へ戻すと委任状の選択は解除されます。

申請書は業務種別9・抹消2、一時使用中止を選択し、車台番号の末尾7文字を記入します。日付と手数料額は任意で、未入力時は空欄にします。金額は窓口等で確認して入力してください。既定の宛先は長野です。所有者・住所変更を伴う申請、永久抹消、輸出抹消、軽自動車の返納には対応しません。

公式OCR様式はA4横・100%で印刷します。ナンバープレートや印鑑証明書等の原本は別途必要です。印刷した様式と記入内容の実機確認は提出前に行ってください。

## ホスティングについて

このアプリは静的ファイルのみで構成されており、**どこか1つのURLで公開する**必要がある
(お店にPC/サーバーを置く必要はない)。GitHub Pages、Netlify、Cloudflare Pagesなど、
静的サイトホスティングであればどこでも動く。HTTPS配信必須(Web Share Target・
Service Workerの要件)。

ローカルでの動作確認は `python -m http.server` 等で行える(`http://localhost` は
セキュアコンテキストの例外のため、HTTPS化しなくてもService Worker等が動作する)。

## 重要: フォントについて(pdf-libの既知の不具合と回避策)

`assets/fonts/NotoSansJP-Regular-static.ttf` は、Google Fonts配布の可変フォント
`NotoSansJP-VF.ttf` から、ウェイト400(Regular)を固定インスタンス化したもの。

**なぜ可変フォントをそのまま使わないか**: pdf-lib(+ @pdf-lib/fontkit)は可変フォント
(OpenType Variable Fonts、`fvar`/`gvar`テーブルを持つフォント)を正しく扱えない。
実機検証の結果、可変フォントのまま`pdf-lib`に渡すと、生成PDFで一部の文字が
ランダムに欠落する不具合を確認した。`fonttools`の`varLib.instancer`で固定ウェイトの
静的インスタンスに変換することで解消する。

**さらに重要: `embedFont`のサブセット化(`subset: true`)も使わないこと**。静的フォントに
変換した後でも、pdf-lib 1.17.1 + @pdf-lib/fontkit 1.1.1 の組み合わせでは、グリフ数の
多い日本語フォントをサブセット化すると大半の文字が欠落する不具合を実機検証で確認した
(1文字ずつ分けて描画しても再現するため、レイアウト起因ではなくサブセット化処理自体の
不具合と判断)。`js/pdfgen.js`では`subset: false`(フルフォント埋め込み)にすることで
回避している。ファイルサイズは1書類あたり約3.4MBに増えるが、印刷は端末内で完結するため
実用上問題ない。

**フォントを再生成する場合**(元の可変フォントを更新した場合等):

```bash
pip install fonttools
python -c "
from fontTools.varLib.instancer import instantiateVariableFont
from fontTools.ttLib import TTFont
f = TTFont('元のVFファイル.ttf')
instantiateVariableFont(f, {'wght': 400}, inplace=True)
f.save('assets/fonts/NotoSansJP-Regular-static.ttf')
"
```

将来pdf-libのバージョンが更新されサブセット化の不具合が修正された場合は、
`js/pdfgen.js`の`subset: false`を`true`に戻せばファイルサイズを削減できる
(その際は必ず実機で全文字が欠落なく描画されるか再検証すること)。

## 未検証・実機確認が必要な項目

この開発環境には実機のAndroid端末・車検証閲覧アプリ・プリンターが無いため、
以下は実機での検証が必要:

- **車検証閲覧アプリからの共有(Web Share Target)が実際に機能するか**。共有時のMIMEタイプ・
  フィールド名は未確認のため、`manifest.json`の`share_target.params`は幅広いacceptを
  指定した推測値になっている。
- **Tesseract.jsによる住民票・印鑑証明書のOCR精度**(サーバー版のPython+Tesseractと
  同等の精度が出るか、処理時間が実用的か)。
- **プリンターへの印刷**(Mopria/AirPrint対応プリンターでの実際の印刷結果、升目の
  位置ズレの有無)。
- **PDF生成の最終的な見た目**(pdf-lib版で座標変換(Y軸反転)を行っているため、
  升目の位置が公式書式と一致しているか、実際に印刷して確認すること)。

## 元のサーバー版(ShakenDocSystem)との違い

- PCサーバー(FastAPI)・Windowsファイアウォール設定・自己署名証明書・SumatraPDF等、
  PCに関するものは一切不要になった。
- 「PC + ICカードリーダー」による車検証読み取り方式は廃止した(スマホの車検証閲覧
  アプリからの直接連携に一本化)。
- 本人確認書類のOCRは、住民票・印鑑証明書のみに対応を絞った(運転免許証等は対象外。
  この2書類のみがこの手続きで有効なため)。カメラは常にこのWebアプリから直接起動する
  (別のアプリを経由する手段は削除した)。
- 委任状の受任者情報(店舗情報)は、サーバーの設定ファイルではなくこの端末の
  `localStorage`に保存する(`settings.html`)。

```

sw.js                 Service Worker(オフラインキャッシュ・共有の受け口)
js/
  procedures.js       手続きの種類の定義(旧app/procedures.pyから移植)
  shakensho.js        車検証データの正規化(旧app/shakensho_import.pyから移植)
  pdf_fields.js        帳票の升目座標データ(旧app/config.pyから移植、数値は無変更)
  pdfgen.js           PDF生成(pdf-lib、旧app/pdf_fill.pyから移植)
  ocr.js              OCR(Tesseract.js、旧app/ocr.pyから移植)
  app.js              画面の配線・状態管理
templates/            国交省配布の公式PDFテンプレート(旧ShakenDocSystemと同じもの)

```
